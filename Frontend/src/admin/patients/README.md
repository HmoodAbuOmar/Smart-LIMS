# Admin Patients

In development, open `/#/__admin/patients` directly, or open `/admin/index.html`
and select **Patients** in the existing Admin sidebar. Other direct previews are
`/#/__admin/overview` and `/#/__admin/users`.
The Admin language control switches all patient UI between English/LTR and Arabic/RTL.
Patient records contain required `nameAr` and `nameEn` fields. `patientName()`
selects the display name everywhere, and search matches both variants. The editor
keeps both entered names when its language control switches the interface;
neither name is automatically translated. Avatar colors are derived from IDs,
while initials follow the displayed name. Identifiers and relationships are unchanged.
The normal Vite build includes both HTML entries, but production loads neither
the Admin demo nor the development routes. The standalone Admin root stays empty
in production. No account/session is created and real authorization is unchanged.

The replaceable `adminPatientsService.js` exports an in-memory asynchronous mock
service. Records survive sidebar navigation during the current application session;
refresh resets them. It makes no HTTP requests and writes no browser storage.
`createPatientsMockService` can supply an isolated fixture set for checks.

Search uses name, file number, or phone. Names and phones are intentionally shared
by different fictional patients. All orders, appointments and transactions use
internal IDs. New file numbers and creator metadata are generated by the service.
Saving accepts only demographic/contact fields and preserves account-link metadata.
There is no delete, account creation/linking, clinical editing, or report printing.

The profile includes overview, orders, appointments and financial summary. Charges
exclude cancelled orders; confirmed payments minus confirmed refunds form net
collections. Pending/failed payments are excluded. Order actions are disabled with
an explanation: the dashboard's existing order dialog does not provide navigation
for this separate patient-owned dataset.

Run from `Frontend`:

```powershell
npm.cmd run dev -- --host localhost --port 5173 --strictPort
npm.cmd run build
npm.cmd run lint
node src/admin/patients/check-patients-model.mjs
node src/admin/patients/check-patients-management-browser.mjs
```

The browser check starts its own temporary Vite server and headless Chrome, verifies
English/Arabic layouts at 1440/768/390/320px, exercises real form interactions and
keyboard focus, and injects mock load/save failures to check recovery. Screenshots
and the Chrome profile are written to the printed temporary directory. Set
`CHROME_PATH` if Chrome is not at the standard Windows installation path.
