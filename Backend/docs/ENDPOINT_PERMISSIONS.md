## Reading the inventory

- **A = ADMIN; P = PATIENT; R = RECEPTIONIST; T = LAB_TECHNICIAN.** Listed roles are exclusive: ADMIN does not inherit PATIENT or technician permissions.
- **A\*** requires both current eligible ADMIN and UUID membership in `smartlims.laboratory.authorized-admin-ids`. Default empty grants no ADMIN clinical access. Route security allows ADMIN first; the service applies this extra restriction.
- **Public** means access JWT is not required or consumed; independent credentials/action proofs and transport checks still apply. All other entries require a valid JWT and current eligible account.
- **Own** means `patients.user_id` equals the authenticated account UUID, reached through the target order where applicable. `created_by` is not patient ownership. Staff-wide access has no assignment restriction unless explicitly stated.
- All unsafe cookie-selected requests require matching CSRF cookie/header. Cookie-login always requires CSRF; logout requires it without recognized explicit Bearer selection. Anonymous unsafe requests may receive 403 before 401. See the report for public-write and malformed-header details.
- Authorization is separate from the workflow/input column. `expectedVersion`, status, capacity, required data, clinical evidence and idempotency keys do not grant privileges. Replays never waive current authorization.
- Shared denials: protected missing/invalid/ineligible authentication is 401 `UNAUTHORIZED`; disallowed role/clinical grant/independent approval or failed CSRF is 403 `FORBIDDEN`. Valid foreign patient IDs generally use concealed resource-specific 404; malformed IDs can be 400. Public login/recovery and account safeguards have the special codes stated in the report.
- Controller references identify mappings; service references identify enforcement and prerequisites. Section security references identify the ordered filter rules. A service reference does not imply method-security annotations; none are enabled.

## Additional enforcement and limits

Notification rows use [PatientNotificationRepository.java:10](../src/main/java/com/smartlims/notifications/repository/PatientNotificationRepository.java#L10) for list/count/read/read-all: patient ownership plus order/appointment integrity and PUBLISHED result visibility. Archive visibility uses [VisitArchiveService.java:49](../src/main/java/com/smartlims/visits/service/VisitArchiveService.java#L49) and [TestResultRepository.java:9](../src/main/java/com/smartlims/results/repository/TestResultRepository.java#L9). These are data filters, not just UI action flags.

Account services rely on HTTP ADMIN guards rather than independent caller authorization. Basic patient CRUD and catalog services check Authentication authorities but do not all recheck persisted role/eligibility; the JWT converter supplies that protection on HTTP. See findings F1/F2. Account role changes do not check retained patient links (F3). Patient value notes are present in result/PDF/trend projections despite ambiguous documentation wording (F4). Approval and publication have distinct identity rules (F6).

No staff order list/detail route, general appointment staff detail/list route, payment controller, general audit-query controller, notification administration/send endpoint, public PDF endpoint, role-grant API for the clinical allowlist, or arbitrary order/result status-update endpoint is implemented. Unsupported requests remain subject to deny-by-default; do not infer a handler from a security wildcard or documentation example.
